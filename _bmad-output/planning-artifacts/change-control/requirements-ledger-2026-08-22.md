# 新一代物流运输系统要求总账

## 使用规则

本文件是后续方案、原型和评审的“不可丢失约束”。新增方向只能扩展或重排这些要求，不能静默删除。任何删除或降级必须在变更提案中逐项说明，并得到明确批准。

| 编号 | 不可丢失要求 | 状态 | 本轮落点 |
|---|---|---|---|
| RQ-001 | 产品是可直接办公的完整物流运输管理系统，不是概念展板或 AI 演示页 | 保留 | 主原型、产品蓝图 |
| RQ-002 | 运输闭环覆盖订单、配载、调度、在途、异常、回单、结算与经营分析 | 保留 | PRD FR-027..056、生命周期导航 |
| RQ-003 | 管车覆盖资产、实时位置、安全、检查、健康、维修、证照、司机、油能和成本 | 本轮扩展 | PRD FR-069..082、车辆运营导航 |
| RQ-004 | 物流老板、车队长、运营管理者、物流专员、调度、司机六类角色都能完成工作 | 保留 | PRD FR-057..068、角色工作面 |
| RQ-005 | 司机使用独立 Driver Companion，支持弱网、异常、回单和行驶安全模式 | 保留 | FR-063..068、独立移动端契约 |
| RQ-006 | 全部业务界面和动作使用中文，保留必要的 G7、编码和车牌 | 保留 | UX 文案基线、主原型 |
| RQ-007 | 交互参考 Codex 的稳定工作区、持久线程、上下文、进度、审批、恢复和结果验证 | 保留并加深 | AI 工作台、Agent Runtime |
| RQ-008 | AI 不是旁边的聊天框；它要能调查、计划、起草、请求批准、调用工具和回读结果 | 保留并加深 | AI 运行线程、工具与审批面 |
| RQ-009 | AI 不暴露隐藏推理文本，只展示证据计划、来源、事实、冲突、未知、动作和结果 | 保留 | FR-019、FR-022、UX Agent Rail |
| RQ-010 | AI 写操作分级：只读、草稿、外部写入、停驶/敏感操作；高风险必须复核 | 保留 | FR-021、FR-023、FR-025 |
| RQ-011 | G7 是底层管车事实与原子能力平台，产品不重复定义稳定对象与平台治理 | 保留 | G7 反腐层、平台边界 |
| RQ-012 | 平台管主数据、统一模型、原子能力和治理；产品管场景编排、体验、聚合和差异 | 保留 | 产品蓝图、架构 AD-038 |
| RQ-013 | 运行时数据按 Snapshot / History / Feed 分层，所有事实标明发生、接收与新鲜度 | 保留 | FR-006、AD-002 |
| RQ-014 | G7 外部写入必须幂等、可恢复并写后回读；不能伪造同步成功 | 保留 | FR-008、FR-025、AD-018 |
| RQ-015 | 参考优秀 TMS，但不照搬传统菜单式 SaaS；生命周期清晰且具体可操作 | 保留 | TMS 工作台、对象抽屉 |
| RQ-016 | 参考优秀管车系统，但车辆能力必须嵌入运输决策，不形成第二座信息孤岛 | 本轮新增 | 统一对象图、运输与车务联动 |
| RQ-017 | 高频办公以队列、筛选、表格、批量动作和对象上下文为主，地图用于空间证据 | 保留并修正 | 主原型三栏工作面 |
| RQ-018 | 不使用抽象的 Analyst/Planner/Operator 模式让业务用户猜；动作随场景出现 | 保留 | 中文任务动作、AI 能力目录 |
| RQ-019 | 一个对象可在摘要、节点/轨迹、健康、工作、费用、凭证、日志之间切换 | 本轮扩展 | 对象抽屉七类标签页 |
| RQ-020 | 任何告警必须能转成有责任人、时限、证据和结果的工作 | 本轮强化 | 安全案件、异常案件、维修工单 |
| RQ-021 | 维护必须形成缺陷/提醒 -> 工单 -> 配件/人工 -> 完工 -> 车辆可用 -> 运力重算闭环 | 本轮新增 | FR-073..076、EP-012 |
| RQ-022 | 油能和支出必须进入单车、单票、线路、客户成本，并能识别疑似异常 | 本轮新增 | FR-078..079 |
| RQ-023 | 车辆、挂车、非动力资产、设备分别建模，通过关系连接 | 本轮新增 | FR-069、AD-039 |
| RQ-024 | 派车前同时校验位置、车型、容量、资格、工时、车辆健康、检查和维护占用 | 本轮强化 | FR-033、FR-072、FR-077 |
| RQ-025 | 管理层能从经营指标下钻到订单、车辆、司机、异常、维护和费用证据 | 保留 | FR-050..055、AI 经营分析 |
| RQ-026 | 原型必须有真实列表、筛选、批量动作、状态、详情、审批、失败和恢复交互 | 保留并强化 | 新主原型验收 |
| RQ-027 | 页面不使用营销式 Hero、装饰卡片和大面积渐变；信息密度适合重复办公 | 保留 | DESIGN、主原型 |
| RQ-028 | 角色切换改变默认首页、字段和动作，但不能扩大权限 | 保留 | FR-057、AD-037 |
| RQ-029 | 安全、隐私、审计、租户隔离、弱网和并发资源锁属于产品能力，不是后补技术项 | 保留 | NFR、架构与状态模式 |
| RQ-030 | 所有产品文档、架构、Epic 和主原型必须指向同一能力范围 | 本轮治理 | 变更提案和同步修改 |

## 能力完整性检查

### 运输管理

- [x] 订单接入、校验、拆合与承诺
- [x] 配载、站点、容量、线路和场景比较
- [x] 人车候选、资源锁、派车发布和 G7 同步
- [x] 在途位置、节点、预计到达、温控与偏航
- [x] 异常影响、恢复、客户沟通和责任闭环
- [x] 签收、回单、凭证、缺件和结案
- [x] 费用采集、合同匹配、对账、差异和核销
- [x] 客户、承运商、SLA、服务案件和经营下钻

### 管车管理

- [x] 车辆、挂车、设备和非动力资产目录
- [x] 当前状态、轨迹、围栏、路线回放与新鲜度
- [x] 驾驶行为、视频安全、风险分级、辅导与复核
- [x] 班前/班后检查、缺陷、停驶和放行
- [x] 故障码、健康度、远程诊断和派车门禁
- [x] 保养计划、提醒、维修工单、配件、人工、供应商和保修
- [x] 车辆/司机证照、资格、到期和审计
- [x] 班次、工时、培训、消息、人车绑定和司机端任务
- [x] 油耗、怠速、加油/充电、费用匹配与异常支出
- [x] 利用率、空驶、停机、每公里成本和全生命周期成本

### AI 工作方式

- [x] 持久线程与可恢复上下文
- [x] 角色和对象作用域锁定
- [x] 证据计划、来源、新鲜度、冲突和未知
- [x] 受控工具、幂等、审批、预算和失败恢复
- [x] 可比较方案和结构化结果
- [x] 写后回读和业务视图刷新
- [x] 自动化流程版本、评估、发布、暂停和回滚
- [x] 经营、调度、异常、安全、维修、油能、合规、客服和数据质量能力

## 2026-08-23 用户之声整改增量

| 编号 | 不可丢失要求 | 状态 | 本轮落点 |
|---|---|---|---|
| RQ-031 | 至少 100 个跨产品、跨角色的 TMS/SaaS 有效问题必须逐条保留证据、根因、整改与验收信号 | 新增并完成 | 120 条问题目录、35 个来源 |
| RQ-032 | 六角色默认首页以今日任务、风险和待审批组织，不以统一 KPI 或模块菜单要求用户理解系统 | 强化 | 角色切换、工作队列 |
| RQ-033 | 高频队列必须具备搜索、组合筛选、保存视图、批量动作、列配置和部分成功重试 | 新增 | UX 基线、后续工程验收 |
| RQ-034 | 所有动态事实显示来源、发生/接收时间和新鲜度；陈旧或冲突数据不得表达为正常 | 强化 | 地图、对象详情、AI 证据 |
| RQ-035 | 地图采用“对象清单 + 空间证据 + 业务详情”双向联动，可搜索、筛选、聚焦并直接处置 | 新增并原型化 | 高德地图工作区 |
| RQ-036 | 地图 SDK、网络或鉴权失败时仍保留文字位置、对象清单和处置入口 | 新增并原型化 | 地图降级态 |
| RQ-037 | 导入、同步和批量写入必须预检、逐项反馈、仅重试失败项并保留幂等与回读 | 强化 | AI/G7/批量操作合同 |
| RQ-038 | 司机端支持弱网离线队列、补传冲突和行驶安全模式，核心任务不依赖持续网络 | 强化 | Driver Companion 合同 |
| RQ-039 | AI 必须按“作用域-证据计划-工具-审批-执行-回读-恢复”完成工作，不能以建议文本冒充完成 | 强化 | Agent Runtime 验收 |
| RQ-040 | 生产地图密钥不得以静态原型方式交付，应使用安全密钥/代理、白名单与轮换 | 新增 | 高德生产接入约束 |

| RQ-043 | 只有平台无对应能力/数据或经证据证明不能满足目标时才允许本地实现；每个本地表、状态机或服务必须关联已批准的 G7-GAP 与 ADR | 新增 | Build Gate、迁移审查 |
| RQ-044 | 开发、测试和预生产默认只用 G7 SANDBOX；PROD 凭据必须存入 Secret Manager，并在 Acceptance Gate 与人工批准后才可绑定 | 新增 | Harness Secret 与 Release Gate |
