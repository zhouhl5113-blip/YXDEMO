# 车队作战台（Fleet Office）PRD

## 1. 产品目标

把 G7 易流开放平台提供的稳定对象与实时事实，编排成车队企业从订单到经营改善可连续完成的工作。内部 Web 服务物流老板、车队长、运营管理者、物流专员、调度及安全/车务/财务/管理员；Driver Companion 服务司机。所有角色共享业务和证据底座，但首页、字段、动作、AI 模式与终端交互按职责组合。

核心 JTBD：

> 当车队发生变化或风险时，我要立刻知道“什么变了、影响谁、下一步做什么”，并在同一上下文中完成处置和留痕，而不是在多个菜单、地图和表格间拼接答案。

## 2. 用户旅程

### UJ-001 车队经理开始一天

进入“今天”工作空间，看到按风险、时效和责任排序的工作流；打开一条延误记录，右侧同时显示车辆、司机、位置新鲜度和关联任务；接手或分派后，记录从“待判断”进入“处理中”。

### UJ-002 调度员完成派车

在命令面板输入订单/线路或从待派任务开始，系统根据组织范围、车辆状态、司机资格和时间冲突给出候选；调度员确认人车与生效时间；系统创建本地派车任务，并同步 G7 人车绑定。

### UJ-003 安全员闭环风险

G7 安全事件进入风险工作流，系统按规则聚合和分级；安全员查看事件事实、轨迹和媒体，联系司机并记录干预；满足关闭条件后完成复核，所有动作进入审计时间线。

### UJ-004 车务人员处理到期

车务人员从到期队列打开车辆档案，看到证照、维护和历史记录；创建办理/维修任务、上传结果并更新有效期；车辆可用性随规则更新，但不直接改写 G7 原始事实。

### UJ-005 调度员用 Agent 恢复异常

调度员从晚到工作创建有作用域的 Agent Thread；系统装配订单、车辆、司机、G7 事实、SOP 和客户 SLA，先展示证据再给出可比较方案；用户批准 R2 改派/通知后，系统执行、回读并生成可交接结果。

### UJ-006 客服与财务完成订单闭环

客服接入订单并校正抽取字段，调度完成计划和派车，在途 ETA 风险生成客户通知草稿；到货凭证满足结案条件后，费用与账单进入证据匹配，财务调查差异并提交受审计调整。

### UJ-007 经理完成晨间决策

经理打开“今天”，AI 简报汇总昨夜变化、未来四小时承诺/安全/运力风险和待批准动作；经理展开证据、比较补运或改约场景，并把决定连同上下文交给责任人。

### UJ-008 安全与车务联合控制风险

安全事件、故障和维护逾期形成跨域影响；安全员与车务分别核实证据，系统合并约束；停运作为 R3 双人复核，执行后刷新车辆可用性并重算受影响订单。

### UJ-009 运营管理员发布自动化

管理员以事件或时间为触发器编排注册工具、条件、审批和回读，用脱敏历史案例模拟；评估和权限门禁通过后按组织灰度发布，失败运行可暂停、恢复、重放或回滚。

### UJ-010 管理层追问经营变化

管理层从统一指标追问线路毛利或准时率变化；Analyst Agent 下钻客户、订单、车辆、司机、事件、维护和费用，区分事实/相关性/推断/未知，并把建议转成场景、任务或 Playbook 跟踪结果。

### UJ-011 物流老板确认经营动作

物流老板打开经营驾驶舱，先看到目标偏差、现金/毛利、客户集中度、资产利用和重大风险；选择异常指标后沿统一口径下钻到组织、客户与订单证据；把结论转成有责任人、截止时间和结果指标的改善任务，而不是直接干预单笔派车。

### UJ-012 车队长完成班前就绪与交接

车队长打开班次控制台，核对出勤司机、资格/工时、车辆可用性、维护占用、待派任务和昨班遗留；处理缺口并发布班次；班末发起结构化交接，下一班必须接受、退回或由超时策略升级。

### UJ-013 物流专员清空履约工作箱

物流专员按 SLA 和阻塞类型处理订单缺字段、客户确认、回单、异常凭证与结算前置项；每个 Fulfillment Case 沿订单生命周期保留来源、责任和下一动作；拆单/合单后阻塞项按证据引用重新投影。

### UJ-014 调度员在排程板发布班次

调度员在时间轴上查看订单时窗、车辆/司机班次和锁定，在地图上核实空间影响，在候选面比较资格、工时、距离和新鲜度；系统临时锁定选择并实时检测并发冲突；批量发布部分失败时保留成功项和可恢复草稿。

### UJ-015 司机在弱网中完成运输任务

司机通过 Driver Companion 轻量认证并接收当前任务，查看下一站、时窗、联系人和必要安全提示；可离线记录接单、到离场、异常和回单，恢复网络后以幂等命令补传；车辆运动时只允许语音提示、导航跳转和紧急上报，复杂输入在停车后继续。

## 3. 产品模型与术语

| 术语 | 定义 | 真相来源 |
|---|---|---|
| 对象 | 车辆、司机、场站/地址、设备等稳定实体 | G7 为主，本地保留映射与业务扩展 |
| 事实 | 位置、速度、车况、事件、围栏进出等带时间的数据 | G7；不可被业务用户改写 |
| 工作 | 派车、处置、维护、办理等有责任人和生命周期的任务 | 本产品 |
| 关联 | 人车绑定、任务与对象关系 | G7 绑定事实 + 本地业务关联 |
| 工作流 | 面向用户、按优先级呈现的事实变化与待办集合 | 本产品读模型 |
| 新鲜度 | 事实的 `happened_at` 与当前时间差，并区分接收时间 | 本产品计算 |

## 4. 功能需求

### 4.1 连续工作面

**FR-001 今日工作流**：系统必须将未接手异常、临近时限任务、在途变化和到期事项组成统一工作流，支持按角色、组织、优先级、状态过滤；每条记录显示对象、原因、发生时间、新鲜度、责任和下一动作。

**FR-002 全局命令面板**：用户必须能通过 `Ctrl/Cmd + K` 搜索车牌、司机、任务、地点和动作；结果按“对象、工作、命令”分组，权限不足的对象不得泄露摘要。

**FR-003 持续上下文**：用户选择任一记录后，右侧上下文抽屉必须保留对象身份、关键事实、关联工作和可执行动作；用户切换工作空间或返回列表时，选择状态可通过 URL 恢复。

### 4.2 车队对象与实时事实

**FR-004 对象目录**：系统必须提供车辆、司机、场站/地址的统一检索与详情，支持组织、标签、属性、外部 ID、状态和权限范围；车辆至少展示车牌、VIN、车型、载重/尺寸、能源类型和归属组织。

**FR-005 人车关系**：系统必须展示当前及历史人车绑定，支持创建、变更和解绑；创建前必须校验同一司机时间重叠、同车同身份时间重叠及结束时间晚于开始时间。

**FR-006 事实视图**：系统必须展示车辆位置/速度、车况和安全事件的快照、增量与历史；每项数据标明来源、发生时间、接收时间和新鲜度，历史查询遵守 G7 的范围与分页限制。

### 4.3 调度与在途协同

**FR-007 派车工作**：调度员必须能创建包含业务单号、线路/场站、计划时间、车辆、司机、责任人和备注的派车任务，并维护草稿、待确认、已派、在途、完成、取消状态。

**FR-008 派车校验与同步**：系统必须在确认前校验权限、车辆可用性、司机/车辆时间冲突和必填资格；确认后以幂等方式同步 G7 人车绑定，失败时保留本地“待同步”状态并允许重试或撤销。

**FR-009 在途时间线**：系统必须将计划节点、围栏进出、位置变化、事件、人工备注和任务动作合并为单一时间线；用户可从任一异常节点创建工作并关联责任人和时限。

### 4.4 安全事件闭环

**FR-010 风险收件箱**：系统必须增量消费 G7 事件 Feed，并依据事件类型、速度、媒体、资产、司机、标签和组织规则进行去重、聚合与分级；默认支持超速、急加速、急减速和疲劳驾驶类事件。

**FR-011 处置任务**：安全员必须能接手、分派、记录联系/培训/停运等干预、设置复核时间并关闭事件；关闭必须有结果分类和说明，高风险关闭需复核角色确认。

**FR-012 证据查看**：在权限允许时，系统必须展示事件关联图片、视频状态、回放日历或外链；媒体不可用、处理中或过期时显示明确状态，不将缺失媒体解释为无风险。

### 4.5 车务合规与维护

**FR-013 一车一档**：系统必须为每辆车汇总主数据、绑定历史、证照/资质、维护、事件、任务和审计记录；证照支持签发日、到期日、附件、标签、归档和恢复。

**FR-014 到期与维护工作**：系统必须按可配置提前期产生证照到期、年检、保养和维修工作；任务包含车辆、规则来源、责任人、计划时间、结果和附件，完成后保留历史版本。

### 4.6 数据治理与平台管理

**FR-015 G7 适配与降级**：系统必须通过服务端 G7 适配层处理签名、租户/用户头、游标、限额、重试、超时和错误映射；外部不可用时使用最后成功事实并显示降级，不得伪造同步成功。

**FR-016 数据交换**：管理员必须能批量导入/导出车辆、司机及业务映射；外部 ID 必须在租户内唯一；导入支持预检、错误行下载和幂等重试，敏感导出需审批与审计。

**FR-017 权限与审计**：系统必须支持租户、组织和标签数据范围，以及管理员、车队经理、调度员、安全员、车务人员、只读审计员角色；所有变更、导出、敏感查看和同步重试必须记录操作者、时间、对象、前后值、请求 ID 与来源应用。

### 4.7 Ops Agent Workbench

**FR-018 Agent 工作线程**：用户必须能从工作流、对象抽屉或命令面板创建带对象、时间窗口、角色作用域和目标的 `AgentThread`；线程包含可恢复的 Turn、运行状态、参与工具、审批请求和最终结果，并可通过 URL、对象档案和班次交接恢复。

**FR-019 证据计划与账本**：Agent 在形成建议前必须生成可见的证据计划，说明将读取哪些 G7/本地数据以及完成条件；每个事实必须记录来源、`happened_at`、`received_at`、请求 ID、权限范围和新鲜度，事实、推断、冲突和未知分栏展示。

**FR-020 Context Pack 与策略**：运行必须按租户、组织和对象作用域加载版本化的租户政策、车队 SOP、路线/时窗约束、司机安全规则、客户 SLA 和监管规则；策略冲突、过期或缺失时必须暂停建议并要求人工确认。

**FR-021 工具注册与分层**：Agent 只能调用注册工具；工具至少分为只读事实、可撤销草稿、外部写入和敏感操作四类，声明输入 schema、数据范围、风险等级、幂等键、超时、可撤销性和审计字段。Agent 不得直接调用 G7 或持有 G7 凭据。

**FR-022 计划、进度与失败恢复**：UI 必须显示 Agent 当前阶段（意图、作用域、证据、方案、审批、执行、回读、完成/失败）、工具状态、耗时、来源和下一步；工具超时、限流、权限不足和证据矛盾必须可重试、改范围、人工接管或恢复线程。

**FR-023 风险分级审批**：R0 只读可自动执行，R1 本地可撤销草稿需用户确认，R2 外部副作用必须逐项批准，R3 停运/资格冻结/敏感导出/批量变更必须双人复核；审批卡必须显示目标、证据摘要、影响、可撤销性和失败回滚。

**FR-024 并行专家与合并**：对于晚到、偏航和高风险事件，编排器可并行运行证据分析、ETA/方案、风险合规和动作草拟专家；专家只返回结构化结论和证据引用，主线程必须合并冲突、标记未知并显示各专家活动与消耗。

**FR-025 写后验证与刷新**：所有 R2/R3 工具执行后必须重新读取本地业务记录和 G7 事实，区分“已生效、待同步、执行失败、回读延迟”；验证完成前不显示“已完成”，并刷新今日工作流、对象抽屉和审计时间线。

**FR-026 运行评估与交接**：管理员必须能按黄金案例回放 Agent 运行，查看证据覆盖率、工具调用、审批和结果；用户可生成班次交接摘要，保留未解决问题、下一步、责任人和上下文压缩后的关键事实。

### 4.8 订单与履约

**FR-027 订单接入与完整性**：系统必须支持 API、表格和文档录入订单，抽取客户、货物、提送点、时窗、服务级别和计费字段；缺字段、冲突字段和重复订单进入可处理队列，原始文件与抽取结果可追溯。
**FR-028 履约计划与停靠点**：系统必须将订单拆分为运输段、停靠点和履约承诺，支持合单、拆单、时窗、容量、装卸时长和路线约束，并生成可比较的计划草稿。
**FR-029 ETA 与承诺风险**：系统必须结合 G7 位置/轨迹事实、计划时窗、历史耗时和运营事件计算 ETA 与风险等级，显示置信度、证据、新鲜度和影响订单。
**FR-030 异常影响传播**：系统必须把车辆、司机、路线、停靠点、订单、客户 SLA 和后续任务组成影响图；异常发生时列出受影响对象、最晚补救时间和责任人。
**FR-031 履约凭证与结案**：系统必须接收签收、异常签收、照片、回单和客户确认，校验订单履约条件并将未满足项转为待处理工作，不得静默标记完成。

### 4.9 运力计划与调度优化

**FR-032 运力池与班次计划**：系统必须按组织、车型、载重、能源、司机资格、班次和维护占用展示可用运力，支持未来日期和临时运力锁定。
**FR-033 候选匹配与约束解释**：系统必须为订单或运输段提供人车候选，解释容量、时窗、资格、位置、工时和冲突约束；候选建议与阻塞原因分开呈现。
**FR-034 What-if 场景**：用户必须能够复制计划并比较准时率、空驶、里程、成本、加班、风险和客户影响；场景计算不能直接写入生产派车。
**FR-035 派车批处理**：系统必须支持按班次、区域或订单批量生成派车草稿，逐项显示冲突和可撤销性，确认后才通过本地服务同步 G7。
**FR-036 运力预警**：系统必须提前识别未来班次的运力缺口、维护占用、司机工时风险和高峰拥堵，并生成补运、改约或客户沟通建议。

### 4.10 客户、伙伴与结算

**FR-037 客户 SLA 与承诺**：系统必须保存客户 SLA、承诺模板、通知渠道、联系人和升级规则，并将订单风险映射到具体承诺。
**FR-038 协同消息工作流**：系统必须从异常或计划变化生成带证据的客户/承运商通知草稿，支持审阅、发送、撤回状态和沟通时间线。
**FR-039 索赔与服务案件**：系统必须支持从订单、凭证、事件和沟通创建服务案件，记录责任、金额、材料、时限、处理阶段和复核结果。
**FR-040 费用采集与匹配**：系统必须接收运费、油费、路桥费、停车、装卸和附加费，按订单、运输段、车辆和供应商匹配并保留来源凭证。
**FR-041 结算对账**：系统必须比较合同费率、实际履约、外部账单和已付款记录，标出差异、重复、缺凭证和需审批金额，不自动篡改财务原账。
**FR-042 客户服务摘要**：系统必须生成按客户、线路和时间窗聚合的准时率、异常、沟通、索赔和费用摘要，并提供证据链接。

### 4.11 自动化、知识与 AI 治理

**FR-043 Playbook 编排**：管理员必须能以事件、时间、规则或人工命令为触发器，编排查询、判断、通知、草稿、审批、写入和回读步骤。
**FR-044 自动化版本与发布**：Playbook 必须有草稿、测试、发布、暂停、回滚和版本差异，发布前显示权限、风险、预算和影响范围。
**FR-045 运行历史与重放**：系统必须保存每次自动化运行的输入、Context Pack、工具、审批、输出、错误和成本，支持脱离生产数据的安全重放。
**FR-046 知识库与引用**：系统必须支持 SOP、合同、SLA、手册和监管材料的版本、生效期、标签、权限、分段索引和引用位置。
**FR-047 知识冲突与影响**：当知识版本冲突、过期或影响现有 Playbook/Agent 时，系统必须创建治理工作并阻断高风险建议，保留旧版本可审计。
**FR-048 Agent/Skill 目录**：系统必须展示 Agent、Skill、Prompt、工具和模型路由的负责人、版本、作用域、风险级别和启停状态。
**FR-049 评估集与质量门禁**：管理员必须能维护黄金案例、数据源 schema、评分器、基准运行和版本对比，未达到证据覆盖、动作正确性或成本门槛的版本不可发布。

### 4.12 经营洞察与持续优化

**FR-050 经营指标语义层**：系统必须统一订单、履约、准时率、空驶、利用率、维护停机、事故、成本和毛利的定义、粒度、时间口径和权限。
**FR-051 根因分析**：用户必须能从 KPI 下钻至客户、线路、订单、车辆、司机、事件、维护和费用证据，并区分事实、相关性和推断。
**FR-052 需求与容量预测**：系统必须支持按客户、区域、线路和日期预测订单量与运力需求，显示预测区间、数据新鲜度和人工调整记录。
**FR-053 线路与客户盈利**：系统必须估算线路、客户和车辆维度的收入、直接成本、异常成本和服务成本，显示口径和不可分摊项。
**FR-054 管理层日报**：系统必须生成可审阅的日/周经营简报，包含目标偏差、重要变化、风险、证据和建议动作，可导出受权限保护的版本。
**FR-055 优化建议闭环**：系统必须将经营建议转为场景、任务或 Playbook，记录采纳、拒绝、实际结果和回溯指标。
**FR-056 AI 使用与成本看板**：系统必须按租户、组织、Agent、模型、工具和业务域展示调用量、延迟、成本、失败、人工接管和收益指标。

### 4.13 多角色工作面与司机闭环

**FR-057 角色工作空间配置**：系统必须按角色提供可版本化的默认首页、导航顺序、字段密度、通知策略、AI 模式和允许动作；一人多角色切换必须显式、可审计，且不得扩大原有数据范围。

**FR-058 经营驾驶舱**：物流老板必须能查看目标偏差、现金/毛利、客户集中度、资产利用、重大风险和改善任务结果；每个摘要必须带口径、时间、新鲜度并可下钻到有权限的证据。

**FR-059 班次控制台**：车队长必须能按班次查看出勤司机、资格/工时、车辆就绪、维护占用、任务需求、现场事项和遗留工作，处理缺口后发布班次并发起交接。

**FR-060 履约工作箱**：物流专员必须能在统一队列中按订单生命周期处理缺字段、客户确认、单证、回单、异常和结算阻塞；拆单/合单不得丢失原证据和未解决责任。

**FR-061 调度排程板**：调度员必须能以时间轴为主、地图为证据、候选比较为操作面完成排程；选择车辆/司机时创建有期限的资源锁，发布前重新校验版本；批量发布部分失败不得重复成功项。

**FR-062 业务交接**：系统必须提供 `待接收/已接受/已退回/处理中/待复核/已完成/已超时` 的交接状态，记录交出人、接收人、班次、作用域、遗留问题、SLA 和升级路径；代理关系必须有时间窗和原因。

**FR-063 司机任务与站点**：Driver Companion 必须向司机展示当前/下一任务、站点顺序、时窗、联系人、必要货物与安全要求，并支持接单、到场、离场和任务完成。

**FR-064 司机异常、消息与回单**：司机必须能结构化上报延误、车辆、货物、安全和无法联系等异常，接收运营消息并提交照片/签名/备注等回单；所有记录关联任务、位置/时间和设备会话。

**FR-065 司机离线命令**：Driver Companion 必须在弱网/断网时本地排队允许的任务命令和附件引用，使用设备 ID、本地命令 ID 与幂等键补传；冲突、重复和超期命令必须向司机与运营显示结果。

**FR-066 驾驶安全模式**：车辆处于运动状态时，Driver Companion 必须禁用文字输入、复杂表单和需要持续视觉关注的操作，只保留语音提示、外部导航、安全确认和紧急上报；无法可靠判断运动状态时采用可配置的保守策略。

**FR-067 角色 AI 策略**：系统必须按角色限制默认 Agent 模式、可读上下文、可调用工具、输出结构和审批能力；司机端只提供任务范围内的只读/结构化 Copilot，不显示 Agent 控制台或高风险工具。

**FR-068 身份、替班与设备会话**：系统必须支持自营/外协司机、临时替班、一人多角色和值班代理；设备会话只绑定当前有效身份和任务，换人/换车时轻量重新认证并保留前后责任边界。

### 4.14 车辆运营与运输联动

**FR-069 混合资产目录**：系统必须分别管理车辆、挂车、非动力资产、车载设备和传感器，支持组织、标签、外部 ID、当前关系、历史关系和使用状态；不得用单一“车辆类型”字段承载不同资产生命周期。

**FR-070 车辆运营总览**：车队长和车务人员必须能按组织、班次、可用性、位置新鲜度、健康、检查、维护、证照和任务占用筛选车辆；每辆车必须展示当前运输、下一占用、阻塞原因和明确下一动作。

**FR-071 车辆检查与缺陷**：Driver Companion 和车务工作面必须支持班前、班后和专项检查，记录检查表版本、设备会话、里程/工时、图片、缺陷和司机声明；缺陷必须进入 `待判断/限制运行/已转工单/已解决` 状态，不得只作为附件归档。

**FR-072 车辆健康与派车门禁**：系统必须聚合故障码、检查缺陷、维护逾期、证照资格、安全限制和人工停驶，形成带来源、严重度和有效期的车辆可用性投影；派车前必须重新校验，警告与硬阻塞分开显示。

**FR-073 保养计划与提醒**：系统必须支持按时间、里程、发动机工时或其组合建立保养计划和提前阈值；提醒可批量分派、暂缓和转工单，暂缓必须记录理由、责任人和新的到期条件。

**FR-074 维修工单生命周期**：车务人员必须能从车辆、缺陷、故障或保养提醒创建维修工单，维护 `待审批/已排程/维修中/待验收/已完成/取消` 状态，并记录问题、原因、措施、服务任务、计划/实际时间、附件和停机影响。

**FR-075 维修资源与成本**：维修工单必须支持配件、库存地点、领用/退回、技师、人工工时、供应商、报价、保修和费用行；完工后成本进入车辆服务历史和经营语义层，不得覆盖来源票据。

**FR-076 完工放行与运力重算**：维修完成必须经过验收和可行驶确认，自动解决关联缺陷/提醒、重算下次保养、更新车辆可用性，并列出受影响班次和运输段；解除停驶属于受审计动作，高风险停驶/放行按 R3 复核。

**FR-077 安全辅导与改善**：系统必须将驾驶行为、视频、风险评分、历史干预、培训和复发情况组成司机安全档案；安全案件可生成辅导/培训任务，完成后跟踪确认、复发和改善结果，不以单次关闭替代效果验证。

**FR-078 油能运营**：系统必须按车辆、司机、运输段和时间展示油耗/电耗、怠速、加油/充电、里程和单位能耗，区分 G7/设备事实、卡交易、人工录入和推算值，并标注缺口与置信度。

**FR-079 油能与支出异常**：系统必须识别位置与交易不一致、油箱变化与加油量不一致、异常频次、非任务时段消费和重复交易，将结果转为可调查案件；系统不得仅凭模型判断直接认定舞弊或冻结司机。

**FR-080 利用率与全生命周期成本**：系统必须按车辆、车型、组织和线路计算利用率、空驶、停机、维修、油能、保险/证照和折旧等成本，显示口径、缺失数据和不可分摊项，并可下钻到订单、工单和原始凭证。

**FR-081 跨域影响传播**：车辆被锁定、限制运行、停驶、进入维修或恢复可用时，系统必须重新计算关联派车、在途运输、未来班次、客户承诺和替代资源，生成有责任人和最晚处理时间的影响工作。

**FR-082 车辆运营智能能力**：系统必须提供车辆就绪检查、缺陷分诊、维修诊断、油能审计、安全调查和利用率分析等对象化智能能力；这些能力复用 AgentThread、Context Pack、Tool Registry、R0-R3 审批和写后回读，不得建立绕过业务服务的第二套 AI 写入通道。

## 5. 非功能需求

**NFR-001 性能与新鲜度**：在正常依赖条件下，“今天”首次可用内容 p95 不超过 2 秒，命令搜索 p95 不超过 500 毫秒；事件 Feed 从 G7 可见到工作流可见的目标 p95 不超过 60 秒。上述目标需在真实租户数据量压测后校准。

**NFR-002 可用性与降级**：核心办公读写月可用性目标 99.9%；G7 暂时不可用不得阻断本地任务查看与处置记录，系统必须显示最后同步时间和影响范围。

**NFR-003 安全与隐私**：G7 access key、签名材料及租户代码只在服务端使用；传输与静态数据加密；默认最小权限；位置、身份和媒体支持脱敏；日志不得记录密钥或完整敏感字段。

**NFR-004 一致性与幂等**：外部接入采用至少一次处理，使用租户、来源、外部 ID/游标/请求 ID 组合去重；同一命令重试不得产生重复任务或重复绑定。

**NFR-005 可观测性**：每次用户动作到 G7 请求必须可通过 request ID/trace ID 关联；监控外部请求成功率、延迟、限流、游标滞后、死信、事实新鲜度和任务同步积压。

**NFR-006 可访问性与兼容性**：核心流程达到 WCAG 2.2 AA 可操作基线；完整键盘导航、可见焦点、非颜色唯一编码、屏幕阅读器名称；支持当前及前一主版本 Chrome/Edge，1440px 桌面为主，1024px 平板可用。

**NFR-007 数据生命周期**：租户可配置业务任务和审计留存期，但法定/合同要求优先；删除采用可恢复软删除与审批，外部事实的删除请求必须记录执行结果；导出与删除均可追踪。

**NFR-008 容量与配额**：每租户必须有查询并发、历史窗口、导出规模和媒体访问配额；接近限制时提前提示，超过限制时返回可行动的错误，不通过无限重试放大 G7 压力。

**NFR-009 Agent 安全与边界**：模型上下文必须经过租户/组织/标签权限过滤和敏感字段脱敏；工具白名单、网络范围、写入范围与审批策略独立配置；R2/R3 未批准执行数为 0，所有拒绝和越权尝试可审计。

**NFR-010 Agent 可验证性**：Agent 输出的事实引用覆盖率必须为 100%；每个建议必须区分事实、推断和未知，并能回放来源、版本、时间、新鲜度、工具输入摘要和写后回读。不得把隐藏思维链作为用户界面或审计材料。

**NFR-011 Agent 性能与成本**：R0 查询首个证据流 p95 不超过 3 秒，R1 草稿 p95 不超过 8 秒；并行专家必须有租户级 token、工具调用和媒体访问配额，达到预算时降级为结构化人工流程。

**NFR-012 Agent 连续性**：线程事件采用追加写入；浏览器刷新、网络中断或班次切换后 30 秒内可恢复最近一次已持久化状态。长线程压缩必须保留对象作用域、关键事实、未解决问题、审批状态和审计引用。
**NFR-013 业务域一致性**：订单、派车、客户、结算、维护和案件状态必须使用显式状态机；跨域更新采用幂等命令和事件关联，不允许仪表盘直接改写事实。
**NFR-014 任务与查询性能**：今天工作台首屏 p95 不超过 2 秒；订单列表、对象搜索和异常影响图 p95 不超过 3 秒；预测、对账和批量 OCR 采用异步任务并显示进度。
**NFR-015 AI 可组合性**：Agent、Skill、Tool、知识和模型路由必须可独立版本化、灰度、回滚和按租户启停；运行记录必须能区分模型版本和工具版本。
**NFR-016 自动化安全**：Playbook 运行必须经过权限、预算、风险和数据范围检查；R2/R3 动作默认不自动执行，失败时有界重试、补偿和人工接管。
**NFR-017 知识新鲜度**：知识项必须带生效/失效时间、来源和版本；高风险回答引用覆盖率 100%，过期或冲突知识不得被静默使用。
**NFR-018 经营口径可重现**：所有指标、预测和利润结果必须保存口径版本、输入快照、计算时间、过滤条件和数据血缘，支持同一版本重算。
**NFR-019 可扩展多角色协作**：工作队列、评论、交接、通知和审批必须支持跨角色协同，且每个角色只能看到其数据范围和所需字段。
**NFR-020 AI 数据治理**：模型上下文必须经过租户/组织/字段脱敏和保留策略；外部模型、远程 MCP 或第三方服务的保留和传输边界必须可配置、可审计。

**NFR-021 角色可用性**：六类核心角色完成各自主旅程时，默认界面不得要求先进入无关工作空间；角色首页首个可执行动作 p95 在 2 秒内可用，角色切换后 1 秒内完成本地重组。

**NFR-022 驾驶安全**：Driver Companion 必须通过驾驶中交互专项评审；行驶中复杂输入、批量操作、Agent 自由输入和非紧急弹窗触发次数为 0，并记录安全模式判定来源。

**NFR-023 移动弱网可靠性**：允许离线的司机命令必须在本地加密保存，网络恢复后最终同步成功率目标 99.5%；同一命令重放不得重复创建节点、异常或凭证。

**NFR-024 移动身份与隐私**：设备会话可撤销、短期有效并绑定有效任务；本地缓存最小化并按完成/过期策略清理，锁屏和通知不得泄露客户、货物或司机敏感信息。

**NFR-025 排程并发一致性**：车辆/司机资源锁必须有版本、所有者和短期过期时间；发布使用乐观并发控制，过期方案不得覆盖已生效派车，冲突必须在 1 秒内反馈给在线调度。

## 6. 状态机与业务规则

### 派车任务

`草稿 -> 待确认 -> 已派 -> 在途 -> 完成`

- `草稿/待确认` 可取消；`已派/在途` 取消需要原因并处理绑定。
- 本地状态与 G7 同步状态分开存储：`未同步/同步中/已同步/失败/已撤销`。
- 外部同步失败不会把已确认的业务动作回写为草稿。

### 风险处置

`新建 -> 已接手 -> 处理中 -> 待复核 -> 已关闭`

- 高风险必须进入 `待复核`；关闭后重新出现的新证据创建修订记录，不覆盖历史。
- 同一来源事件的重复 Feed 更新合并到原事件时间线。

### 数据新鲜度

- 新鲜：未超过对象类型阈值。
- 延迟：超过阈值但仍可展示。
- 失联：超过失联阈值或网关状态指示离线。
- 未知：没有足够事实。未知不得显示为正常。

### Agent 运行

`意图 -> 作用域 -> 证据计划 -> 检索 -> 假设/冲突 -> 方案 -> 审批 -> 执行 -> 回读 -> 刷新 -> 审计/交接`

- 运行没有通过证据计划和作用域校验时，不得调用写工具。
- R2/R3 动作必须持有未过期审批令牌；审批内容、策略版本和批准人写入审计。
- 工具执行成功不等于业务已生效；只有写后回读确认才可进入完成态。
- Agent 无法区分事实与推断时必须输出“未知/需人工确认”，不允许用语言自信掩盖缺失数据。

### 业务交接

`待接收 -> 已接受 -> 处理中 -> 待复核 -> 已完成`

- `待接收` 可由接收人退回；退回必须有原因并回到原责任人/值班池。
- 超过接收或处理 SLA 进入 `已超时` 并按组织策略升级，不静默改变责任人。
- 交出人或接收人离开有效班次时重新校验代理与审批资格。

### 调度资源锁

`可用 -> 临时锁定 -> 已发布/已释放/已过期`

- 同一车辆/司机在重叠时间窗只能有一个有效锁；锁带 `reservation_version` 和短期 TTL。
- 发布前重新检查资格、工时、车辆状态、任务版本和锁所有者。

### 司机任务与离线命令

`待接单 -> 已接单 -> 前往站点 -> 已到场 -> 作业中 -> 已离场 -> 已完成`

- 取消、拒绝、无法到达和紧急中止形成显式分支，不伪装成完成。
- 离线命令状态为 `本地待传/同步中/已接受/冲突/已拒绝/已过期`；来源事实冲突时并列保留并转运营处理。

### 订单履约

`接入 -> 待校正 -> 已计划 -> 已派车 -> 在途 -> 已送达 -> 已结案`

- 合单/拆单生成运输段版本，不覆盖来源订单；订单承诺与派车执行分别拥有状态。
- 缺签收、回单或异常说明时不得结案；缺失项生成有责任和时限的工作。

### 客户沟通与服务案件

`草稿 -> 待批准 -> 发送中 -> 已送达/失败 -> 已归档`

- 外发消息为 R2；收件人、渠道、消息版本、批准和回执进入同一时间线。
- 消息失败不回滚异常处置，生成可重试/改渠道的协同工作。

### 结算差异

`新建 -> 自动匹配 -> 调查中 -> 待批准 -> 已确认 -> 已关闭`

- 合同、履约、凭证和外部账单保持来源不可变；调整只形成提案/接口命令，不静默改写财务原账。

### Playbook

`草稿 -> 模拟通过 -> 待批准 -> 已发布 -> 已暂停/已回滚`

- 发布版本不可变；扩展工具、数据范围、风险或预算必须重新模拟和审批。
- 重放必须复用幂等键与已完成步骤，避免重复外部动作。

## 7. 集成约束

| 能力 | G7 接口形态 | V1 策略 |
|---|---|---|
| 车辆/司机主数据 | Create/Search/Get/Update | 服务端适配；定时对账 + 按需刷新 |
| 人车绑定 | Create/Update/Unbind/Search/Snapshot | 派车确认后幂等同步，冲突前置校验 |
| 位置与车况 | Snapshot/Feed/History | 快照供读、Feed 驱动变化、History 按需查 |
| 安全事件 | Historical/Feed/Update | 游标消费、规则分级、本地处置闭环 |
| 围栏进出 | Search | 生成在途节点；不以地图绘制代替记录 |
| 证照/媒体 | CRUD/Archive/Playback/Retrieval | 权限检查后代理访问，保存业务关联 |
| 行程分段 | Search，当前标记 developing | 仅特性开关实验，不作为 V1 验收依赖 |

所有 G7 请求的必需头、签名和租户信息由服务端注入；浏览器只调用本产品 API。

## 9. 验收边界

### V1 Core Workbench 必须通过

- UJ-001 至 UJ-005、UJ-007、UJ-008 与 UJ-011 至 UJ-015 的端到端流程可在对应角色工作面完成；UJ-006 至少通过订单接入、履约、客户草稿和凭证结案。
- G7 沙箱或受控桩环境可验证车辆检索、人车绑定、车辆快照、事件 Feed、位置历史、围栏记录和证照读取。
- 外部超时、限流、游标失效、重复事件、权限不足和敏感数据脱敏有可见且可恢复的行为。
- 每个业务写操作在审计日志中可追踪。
- 晚到恢复黄金案例可完成完整 Agent 线程：作用域锁定、证据计划、并行读取、可比较方案、R2 批准、G7 同步、写后回读、刷新和班次交接。
- R0/R1/R2/R3 四级工具策略、越权拦截、审批过期、G7 失败和线程恢复均有可验证行为。
- 角色切换不扩大权限；调度并发锁、交接退回/超时、司机弱网重放、临时替班、行驶安全模式和 G7/司机事实冲突均有可验证行为。

### V1.5 必须通过

- UJ-006 完成到结算差异关闭；UJ-009 完成 Playbook 模拟、发布、暂停、恢复和回滚。
- 运力场景、客户渠道、费用匹配、知识冲突和自动化运行均有权限、失败恢复和审计证据。
- 检查缺陷可转维修工单，工单包含配件/人工/供应商和费用，完工验收后更新车辆可用性、保养周期并重算受影响运力。
- 油能交易与车辆位置/液位事实可形成调查案件，结论保留证据与人工复核，不直接认定责任。

### V2 必须通过

- UJ-010 的指标口径、下钻、预测/盈利、建议转工作和结果回溯可重现。
- AI 成本、质量、人工接管和业务结果可按租户/组织/Agent/模型/工具查询。

### 不构成 V1 阻塞

- 无人值守自动派车、安全停运、司机资格冻结、替代财务总账、原生 iOS/Android、商业导航和 G7 行程分段接口生产化；这些不阻止 PWA/小程序司机闭环和完整工作台分期交付。
